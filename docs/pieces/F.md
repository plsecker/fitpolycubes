# Engineering History: F Pentacube Catalogue

## Catalogue Overview
The F-pentomino (5/9) catalogue tracks the tiling and packing data for the F piece in 3D and 4D boxes. The catalogue is responsible for maintaining a strict, mathematically sound historical record of prime boxes, impossible families, and published solutions.

## Authoritative Published Sources
- **Primary Source**: Shirakawa's Box Packing Collection (F)
- **URL**: `https://puzzlewillbeplayed.com/Shirakawa/F.html`
- **Credits**: Torsten Sillke (1993-1996), Michael Reid, Toshihiro Shirakawa (2015), Hamlyn.
- **Status**: The source explicitly states "3D Complete."

## Initial Catalogue State
Prior to the audit, the `F_CATALOGUE` contained:
- 54 prime boxes.
- 1 explicitly searched box with no solution (`4x6x10`).
- 16 non-canonical entries in `RAW_PRIMES` (e.g., `Box(3,10,6)` instead of `Box(3,6,10)`).
- An empirical impossibility rule for `a == 2` ("Empirically, no thickness-2 box is tileable by F. All audited 2xbxc cases are impossible.").
- An empirical impossibility rule for cubes (`a == b == c`).

## Every Investigation Performed
1. **Canonicality Check**: Investigated the `RAW_PRIMES` list and identified 16 entries that were not in sorted canonical form.
2. **Impossibility Rule Provenance**: Investigated the justification for the `a == 2` and `a == b == c` impossibility rules. Found no published authoritative source or formal theorem backing these infinite families.
3. **Audit Output Analysis**: After removing the `a == 2` rule, the audit script flagged 39 `2xMxN` boxes as "Unknown composites". Investigated the origin of these 39 boxes to determine if they represented actual exhaustive search data.

## Every Proposed Change
1. Fix the 16 non-canonical entries in `RAW_PRIMES`.
2. Remove the empirical impossibility rule for cubes (`a == b == c`).
3. Remove the empirical impossibility rule for thickness-2 boxes (`a == 2`).
4. (Later Proposal) Restore the `a == 2` rule with the justification "empirically there are no solutions".
5. (Later Proposal) Add the 39 "Unknown" `2xMxN` boxes to `SEARCHED_NO_SOLUTION` to preserve the empirical evidence without generalizing to an infinite family.

## Every Accepted Change and Why
- **Fixed 16 non-canonical entries**: Accepted to maintain the strict canonicality standard of the catalogue.
- **Removed `a == b == c` rule**: Accepted because there was no published source or theorem stating all cubes are impossible for piece F.
- **Removed `a == 2` rule**: Accepted because it was a generalization from finite evidence. The catalogue rules strictly forbid inferring infinite families or replacing evidence with assumptions. It was replaced with a historical comment documenting its removal.

## Every Rejected Change and Why
- **Rejected restoring the `a == 2` rule as "empirically there are no solutions"**: Rejected because it still violates the core mathematical rule against generalizing from finite evidence or inferring infinite families. A box/family is impossible *only if* an authoritative source explicitly states it or an existing theorem proves it.
- **Rejected adding the 39 `2xMxN` boxes to `SEARCHED_NO_SOLUTION`**: Rejected because the number 39 and the specific list of boxes were generated by the `audit_catalogue.py` script (which simply tests all valid-volume boxes up to 15x15x15 against the catalogue's logic). They were not the result of an actual, documented exhaustive search. Adding them would constitute fabricating search evidence.

## Solver Results That Influenced the Catalogue
No direct solver results were used to modify the catalogue during this audit. The catalogue auditing process is strictly a documentation task, not a search task.

## Remaining Unknown Composites
There are currently 39 unproven composites up to 15x15x15. These are entirely composed of the `2xMxN` family (e.g., `2x2x5`, `2x3x10`, ..., `2x15x15`) which are no longer marked as impossible due to the removal of the empirical rule.

## Open Questions
- Are the `2xMxN` boxes actually impossible? If so, can they be proven impossible via a formal theorem, or can exhaustive search logs be produced and documented to add them to `SEARCHED_NO_SOLUTION`?

## Lessons Learned
- **Do not conflate audit script output with search evidence**: The audit script generates a bounding box of test cases to verify the catalogue's logic. The fact that the script tests a box and finds it "Unknown" does *not* mean the box was exhaustively searched by a solver.
- **Strict adherence to provenance**: Empirical rules must be stripped unless backed by a theorem or published source, even if the empirical rule is highly likely to be true.

## Current Catalogue Status
The F catalogue is fully validated, strictly adheres to published sources, and is free of unproven empirical generalizations.
