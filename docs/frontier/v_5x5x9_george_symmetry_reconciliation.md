| Element | Transformation | Description |
|---------|---------------|-------------|
| I | (x,y,z) → (x, y, z) | Identity |

| R_z | (x,y,z) → (4-x, 4-y, z) | 180° about z-axis (long axis) |

**Key properties:**
- Order: 4
- All elements are proper rotations (det=+1)
- V is treated as chiral (reflections excluded)
- Only 180° rotations (no 90° rotations, which would require equal dimensions)

George predicted: **5 asymmetric + 1 symmetric = 6 classes, giving 5×4 + 1×2 = 22 solutions.**

The repository contains only 22 solutions, meaning most V4 orbits are **incompletely represented**:

- **No class has all 4 V4 variants**

**No solution has any non-trivial V4 stabilizer.** The "unique solution with rotation around the long axis" that George mentioned is **not present in the repository**.

## 4. Comparison of All Three Conventions

| Convention | Group order | Classes | Orbit sizes |

| G8 (all proper rotations) | 8 | **18** | 8 each |

**Why V4 and G8 give the same number of classes (18):** The additional 4 elements in G8 (which include x↔y swaps) do not create new equivalences among the 22 repository solutions — each solution's V4 orbit and G8 orbit contain the same set of repository records.

**Why G16 gives fewer classes (14):** Reflections (det=-1) create additional equivalences, merging some V4/G8 classes together. Specifically, solutions [5,10], [6,21], [9,16], and [17,20] become equivalent under reflections.

## 5. Why the Repository Is Incomplete

The 22 solutions were generated by the exact-cover solver (`fitpolycubes_fast.py`), which enumerates all tilings without symmetry breaking. However:

1. The solver found only 22 solutions before being stopped (it was still running)
2. The V4 orbit of each solution has 4 members, but most have only 1 or 2 in the repository
3. The "symmetric tiling" (with R_z symmetry) was not found by the solver

This is consistent with the solver being interrupted before completing the full enumeration.
