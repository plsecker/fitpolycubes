# Frontier Method

## 1. Overview

The Frontier method solves a three-dimensional polycube tiling problem by processing the box in the **z direction**.

At any point in the search, the box is divided conceptually into two parts:

* the portion that has already been processed; and
* the portion that remains to be processed.

The **frontier** is the interface between these two regions.

The search does not need to retain the complete history of how the processed region was constructed. It needs the information at the frontier that can affect the ways in which the remaining region can be completed.

This gives a much smaller description of a partial tiling than a conventional placement search.

## 2. Conventional placement search

In a conventional exact solver, a partial solution can be thought of as a sequence of decisions:

```text
place piece
    ↓
place another piece
    ↓
place another piece
    ↓
...
```

The state of the search implicitly contains the complete arrangement produced by those decisions.

This creates a large search tree. Two different sequences of placements may produce partial tilings whose differences have no effect on the part of the box that remains to be filled.

A conventional search nevertheless treats them as different branches and repeats the same work below them.

## 3. Frontier search

The Frontier method instead asks:

> What information about the processed part of the box is still relevant to the unprocessed part?

That information is represented by the frontier state.

A typical search therefore looks like:

```text
initial frontier
       |
       v
 frontier state
       |
       +---- legal transition ----> state A
       |
       +---- legal transition ----> state B
       |
       +---- legal transition ----> state C
```

Each transition advances the partial tiling in the z direction.

The search continues until either:

* the frontier reaches the end of the box, giving a complete tiling; or
* the current frontier state has no legal continuation.

## 4. Shared frontier states

The most important consequence of this representation is that **different placement histories can lead to the same frontier state**.

For example:

```text
history A ───────┐
                 ├──> frontier F
history B ───────┘
```

History A and history B still represent different partial tilings. They must not be regarded as the same tiling.

What is the same is the **remaining subproblem**.

Once the search reaches frontier `F`, the legal ways of completing the unprocessed part depend on `F` and on the remaining box, rather than on the detailed history that produced `F`.

This allows the solver to reuse the computation of the remainder.

### Decision problems

Suppose the question is simply:

> **Is this box tileable?**

If several different histories reach the same frontier state, the solver can solve the continuation from that state once.

If the continuation is impossible, then it is impossible for every history reaching that state.

If the continuation succeeds, then every history reaching that state has at least one completion.

For a pure existence question, the different histories therefore do not need to be searched independently once their common frontier state has been reached.

### Enumeration and counting

The situation is different when the objective is to enumerate or count tilings, or to establish uniqueness.

The histories reaching the same frontier state still represent different tilings or different partial tilings. They cannot simply be discarded.

Instead, the solver can reuse the computation of the **shared remainder** while retaining the multiplicity or identity of the different histories, as required by the particular objective.

The important distinction is therefore:

> **Different histories share the same continuation problem; they do not necessarily represent the same tiling.**

This distinction is central to understanding the power of the Frontier representation.

## 5. Advancing the frontier

The frontier advances through successive regions of the box in the z direction.

A legal transition extends the already-processed part without violating the geometry of the polycube or the occupancy constraints of the box.

The exact representation of the frontier, and the information retained in each state, is described separately in the state documentation.

The essential requirement is:

> A frontier state must contain enough information to determine all possible legal continuations, while discarding information that can no longer affect those continuations.

This is the central correctness requirement of the method.

## 6. Exactness

The Frontier method is intended to be an exact search, not a heuristic search.

For a given box and polycube, the search explores the reachable frontier states generated by legal transitions.

The two key properties are:

1. **Completeness:** every valid tiling has a corresponding sequence of frontier transitions.
2. **Soundness:** every completed sequence accepted by the search corresponds to a valid tiling of the box.

State sharing does not compromise exactness. When two histories reach the same frontier state, they have the same remaining subproblem by definition of the state representation.

Sharing the solution of that remaining subproblem is therefore valid, provided the solver retains whatever information is required by the overall objective.

## 7. Why the reduction can be large

The number of possible complete placements of pieces can be enormous.

The number of distinct frontier states can be much smaller because the frontier discards information that has become irrelevant to the unfinished portion of the box.

The method therefore exploits two forms of compression:

* **geometric compression:** information behind the frontier no longer needs to be represented in full;
* **shared subproblems:** many different placement histories can lead to the same frontier state and therefore share the computation of the remaining problem.

The second point is especially important. The computational gain does **not** require the different histories to represent the same tiling.

They are different tilings or partial tilings; they simply happen to have the same future problem.

Additional structure discovered during the S-piece and z-direction investigations can reduce the search further. These reductions are documented separately rather than being assumed as part of the basic Frontier definition.

## 8. Frontier states as a mathematical object

It is useful to think of the search as constructing a directed graph.

Each node represents a reachable frontier state.

Each directed edge represents a legal transition that advances the frontier.

```text
          ┌─────────┐
          │ State A │
          └────┬────┘
               |
          ┌────┴────┐
          v         v
     ┌─────────┐ ┌─────────┐
     │ State B │ │ State C │
     └────┬────┘ └────┬────┘
          |           |
          └─────┬─────┘
                v
          ┌─────────┐
          │ State D │
          └─────────┘
```

Several different placement histories may map onto the same node.

The node therefore represents a **shared continuation problem**, not a unique tiling.

This viewpoint is important because the Frontier method is not merely a faster way of walking through the same search tree.

It changes the object being searched.

Instead of independently recomputing the remainder for every placement history, the solver identifies histories that reach the same frontier state and shares the computation below that state.

## 9. Case-specific structure

The basic Frontier method is general. The detailed structure of the frontier can depend strongly on the polycube and the box dimensions.

The repository therefore separates the general method from case-specific investigations.

The `s_piece/` work examines concrete frontier behaviour for the S polycube.

The `z_direction/` work studies the structure that arises as the frontier advances through the box in the z direction, including state growth, shifts, components, recurrence, symmetries, and related invariants.

Those results are not all required to understand the basic algorithm. They represent progressively deeper structure discovered by examining the Frontier state space.
